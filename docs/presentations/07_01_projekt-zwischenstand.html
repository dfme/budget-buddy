04 — KI in unserer Methodik

KI arbeitet an zwei Stellen — im Prozess und im Produkt

Prozess

KI als Mitentwickler im Workflow

Claude Code Skills
  • implement-issue — Issue lesen, Plan zur Freigabe vorlegen, Branch + Code + Tests, lokaler Review, PR öffnen.
  • review-pr — Diff gegen das Issue prüfen, Tests selbst ausführen, Befunde als blockierend/nicht-blockierend trennen.
  • Automatisches PR-Review — läuft zusätzlich bei jedem PR-Event via GitHub Action, ersetzt aber nie die Freigabe durch einen Dev.
  • plan-sprint — Backlog-Hygiene, Velocity und Abhängigkeiten aus dem Board ableiten.
Produkt

KI als Feature in der App

Hybrid-Kategorisierung
  • Lookup zuerst — deckt ~70–80% der Transaktionen kostenlos und deterministisch ab.
  • Claude Haiku, gebündelt — bis zu 20 Transaktionen pro Request, für den Rest.
  • Datenminimierung — IBAN, Beträge und Namen werden vor jedem Claude-Call maskiert.
  • Resilienz — Timeout + Fallback „Sonstiges", Circuit Breaker nach 3 Fehlversuchen.
Mensch bleibt Gatekeeper — KI schlägt vor, gemerged wird nur von einem Dev.

07 — Risiken & Learnings

Was uns wachhält

01
Churn-Falle
Manueller PDF-Import + Kategorisierung führt zu Nutzungsabbruch nach dem ersten Aha-Effekt.
02
Liability & Compliance
Sensible Transaktionsdaten sind ein Hacking-Ziel — ein Datenleck ist existenzbedrohend.
03
Feature-Lücke der Banken
UBS, Raiffeisen & Co. bauen eigene PFM-Tools — der Business Case kann über Nacht wegfallen.
Learning aus #192

Der vollständig synchrone Import lief bei ~110 Transaktionen reproduzierbar ins 30-Sekunden-Zeitbudget und verwarf den gesamten Import. Lösung: Parsen bleibt synchron, Kategorisierung läuft als Async-Job mit Fortschritts-Polling (ADR-14) — ein Import geht seither nie mehr verloren.
